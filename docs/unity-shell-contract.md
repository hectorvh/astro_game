# Unity ↔ shell message contract

The web app (the "shell") runs the Unity WebGL build in an iframe at
`/game-build/play.html`. `play.html` is maintained in this repo (it is not
generated by Unity) and is the only place that talks to both sides.

Keep this file in sync with the Unity repo. If either side changes a message,
update both repos in the same release.

**Rule:** messages carry navigation and settings only. Never put personal data,
participant ids or research answers in them. Research data goes through the
shell's data-access layer.

## 1. Shell → Unity: URL query

```
/game-build/play.html?level=<1-4>&embed=1&muted=<0|1>
```

| Param   | Meaning                                                                 |
| ------- | ----------------------------------------------------------------------- |
| `level` | Level id chosen in the menu (`lib/jerboa/levels.ts`). Default `1`.      |
| `embed` | Always `1` when the shell embeds the player. Unity can hide its own quit/title UI. |
| `muted` | `1` if the participant muted sound in the menu, else `0`.               |

Unity reads these from `Application.absoluteURL`. `play.html` also exposes the
level as `window.astroBunnyShell.level`.

The shell builds this URL once when the game opens (`unityPlayerUrl()` in
`lib/jerboa/unity-messages.ts`). Changing mute later does **not** reload the
iframe; see section 3.

## 2. Unity → shell: `window.parent.postMessage`

Plain objects, posted with `targetOrigin = location.origin` (never `'*'`).

| Message                                         | Sent by                     | When                                               | Shell does                                  |
| ----------------------------------------------- | --------------------------- | -------------------------------------------------- | ------------------------------------------- |
| `{ type: 'ready' }`                             | `play.html`                 | `createUnityInstance` resolved                     | Re-sends the current mute state             |
| `{ type: 'levelComplete', level: number }`      | Unity via `play.html`       | After Unity's level-clear screen                   | Marks the level done; level 1 → debrief video, then menu; other levels → menu |
| `{ type: 'exit', reason: 'pause-menu' \| 'quit' }` | `play.html`              | Participant left mid-level                         | Back to the menu, no video                  |
| `{ type: 'astroBunnyExit' }` *(legacy)*         | `play.html`, older builds   | Same as `exit`                                     | Same as `exit`. Remove after one release.   |

The shell accepts a message only if `event.source` is the game iframe and
`event.origin` is the page's own origin. Unknown types are ignored. Only the
**first** `levelComplete` or `exit` per game session is acted on.

### How Unity sends `levelComplete`

Call the helper `play.html` installs, from a `.jslib` plugin:

```js
// Assets/Plugins/WebGL/ShellBridge.jslib
mergeInto(LibraryManager.library, {
  ShellLevelComplete: function (level) {
    if (window.astroBunnyShell) window.astroBunnyShell.levelComplete(level);
  },
});
```

```csharp
[DllImport("__Internal")] private static extern void ShellLevelComplete(int level);
// After the level-clear screen:
#if UNITY_WEBGL && !UNITY_EDITOR
ShellLevelComplete(levelId);
#endif
```

`levelComplete` sends once per page load and is ignored after an exit.

### Exits

`play.html` sends `exit` itself. Use `reason: 'pause-menu'` when the participant
taps Exit in the pause menu (the overlay hit area), and `reason: 'quit'` when
Unity's `Application.Quit()` runs. Unity does not need to post anything for
exits.

## 3. Shell → Unity: `postMessage` into the iframe

```js
{ type: 'setMuted', muted: boolean }
```

Sent when the participant toggles mute while the game is open, and again on
`ready` so a toggle during loading is not lost. `play.html` accepts it only from
`window.parent` with the same origin, and forwards it to Unity:

```js
unityInstance.SendMessage('AudioManager', 'SetMutedFromShell', muted ? '1' : '0')
```

`play.html` also sends `SetMutedFromShell('1')` right after loading when the URL
has `muted=1`.

**Unity side:** a GameObject named `AudioManager` in every scene (or
`DontDestroyOnLoad`) with:

```csharp
public void SetMutedFromShell(string value) {
    AudioListener.pause = value == "1"; // or set the master mixer volume
}
```

## 4. Testing without a Unity build that sends `levelComplete`

In `pnpm dev` only, while the game screen is open:

```js
__astroBunnyDev.completeLevel(1) // same handler as a real levelComplete message
```
